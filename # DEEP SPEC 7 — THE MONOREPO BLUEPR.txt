# DEEP SPEC 7 — THE MONOREPO BLUEPRINT

**System:** DSRT COCO
**Layer:** Source Organization, Build System, Development Workflow
**Status:** Approved & Locked Specification
**Governing Standards:** All prior Deep Specs (1-6); Constitutional Dimension 4 (13 Fabrics)
**Purpose:** Establish the physical layout, build system, language boundaries, testing infrastructure, and development workflow that makes 13 fabrics, 134+ specialists, and a growing platform maintainable at scale.

---

## 0. MONOREPO PHILOSOPHY

The monorepo is not a folder. It is **the organizational contract** that lets 13 fabrics evolve independently while maintaining a single source of truth for protocols, schemas, and shared types.

### The Ten Governing Laws of the Monorepo

```text
LAW 1  — ONE REPO, MANY BOUNDARIES
         All COCO code lives in one repo. Package boundaries are strict —
         a package may only depend on packages listed in its manifest.

LAW 2  — LANGUAGE-PER-JOB, NOT LANGUAGE-PER-TEAM
         Python for AI/agent/orchestration. TypeScript for user surfaces.
         Go for high-throughput fabric services. Rust for security-critical
         sandbox runtime. No language is used because someone "prefers" it.

LAW 3  — PROTOCOL IS THE SOURCE OF TRUTH
         Every cross-fabric contract is defined in .proto files.
         Code in every language is GENERATED from these protos.
         Hand-written cross-fabric types are banned.

LAW 4  — EVERY PACKAGE IS SEPARATELY BUILDABLE AND TESTABLE
         `just build <package>` and `just test <package>` must work in isolation.
         No package requires "run the whole thing" to be validated.

LAW 5  — CI IS THE ONLY MERGE AUTHORITY
         No PR merges to main without: format ✓ · lint ✓ · type ✓ ·
         test ✓ · security ✓ · protocol-schema ✓ · dependency-audit ✓

LAW 6  — LOCAL DEV MATCHES PROD TOPOLOGY
         `just up` starts the same fabric topology developers will deploy.
         "Works on my machine" is a bug, not an excuse.

LAW 7  — DEPENDENCIES ARE PINNED, AUDITED, MINIMAL
         Every dependency is pinned to a specific version.
         Every dependency is license-scanned and CVE-scanned in CI.
         New dependencies require justification in the PR.

LAW 8  — TESTS ARE FIRST-CLASS ARTIFACTS
         Test code has the same review bar as production code.
         Test coverage is measured, tracked, and non-negotiable per package.

LAW 9  — RELEASES ARE ORCHESTRATED, NOT ANNOUNCED
         Every deployable artifact has: version · changelog · signed image ·
         rollback plan · SBOM · verification report.

LAW 10 — DEVELOPER EXPERIENCE IS A FEATURE
         From `git clone` to running COCO locally: ≤ 15 minutes on any
         supported platform. If it takes longer, that is a P1 incident.
```

## 1. TOP-LEVEL REPOSITORY LAYOUT

```text
coco/
│
├── README.md                              # Entry point — start here
├── LICENSE
├── CONTRIBUTING.md
├── CODE_OF_CONDUCT.md
├── SECURITY.md                            # Vuln disclosure policy
├── CHANGELOG.md                           # Auto-generated (release-please)
├── .github/                               # PR templates, issue templates
├── .editorconfig                          # Uniform whitespace rules
├── .gitignore
├── .gitattributes                         # LF everywhere; binary lockfiles
├── .env.example                           # Every env var COCO reads
├── justfile                               # Task runner (see §10)
├── Makefile                               # Thin wrapper → justfile
│
├── docs/                                  # Human docs (not code)
├── constitution/                          # Executable constitution (§16)
├── protocols/                             # .proto files (source of truth)
├── schemas/                               # JSON Schemas, DB migrations
├── apps/                                  # User-facing surfaces
├── services/                              # Long-running fabric services
├── packages/                              # Reusable libraries per language
├── agents/                                # Agent definitions (YAML + code)
├── operators/                             # Tier-4 operator implementations
├── infrastructure/                        # IaC, deployment manifests
├── tools/                                 # Dev tooling scripts
├── evaluation/                            # Benchmarks, evaluators, datasets
├── tests/                                 # Cross-package integration tests
├── examples/                              # Example missions, corpora
└── vendor/                                # Third-party we've forked (rare)
```

### 1.1 Rationale for Top-Level Directories

```text
docs/                → Human-only. Never imported. Renders on the docs site.
constitution/        → Constitution YAML/JSON that loads into runtime.
protocols/           → Protobuf definitions. Generated stubs live inside packages/.
schemas/             → JSON Schemas + SQL migrations. Loaded at runtime.
apps/                → Everything users see or invoke directly.
services/            → Everything users don't see but depends on the network.
packages/            → Libraries: importable Python, TS, Go, Rust.
agents/              → All 134+ agent definitions, prompt templates.
operators/           → The 5 Tier-4 operator implementations.
infrastructure/      → Deployment (Docker, K8s, Terraform).
tools/               → Scripts developers run (not services).
evaluation/          → Benchmarks + graders + datasets for continuous elevation.
tests/               → Integration + system tests spanning packages.
examples/            → Reference missions/corpora for onboarding.
```

### 2.1 Key Rules for `apps/`

```text
1. Apps are LEAF nodes in the dependency graph — nothing depends on them.
2. Apps depend on packages/ and services/ (via generated clients).
3. Every app has a README describing: run locally, build, test, deploy.
4. Every app has feature flags via packages/feature-flags.
5. No app makes direct DB calls — always via the Gateway service.
```

### 3.1 Service Boundaries — Language Justification

```text
SERVICE                    LANGUAGE    JUSTIFICATION
──────────────────────    ─────────   ─────────────────────────────────────────
gateway                   Go          High QPS · mTLS termination · low GC pause
kernel                    Python      Complex orchestration · rich async · agent code
context-service           Python      Memory/vector integration · Python ML libs
intelligence-service      Python      Agent runtime · model calls · Python ecosystem
execution-service         Go          Sandbox pool mgmt · goroutine-per-sandbox
sandbox-runtime           Rust        Security-critical · memory-safe · minimal deps
forge-service             Python      Repo generation · leverages agent infrastructure
verification-service      Python      Check orchestration · rich Python ecosystem
brain-service             Python      Knowledge graph · vector · rich domain code
evolution-service         Python      Data science · sklearn/numpy · nightly jobs
security-service          Go          Token issuance · crypto perf · deterministic
event-bus                 —           NATS binary + config only
observability-collector   —           OTel binary + config only
memory-service            Python      Vector + graph + provenance in one place
inference-gateway         Python      Provider adapters + streaming
check-runners             Python      Test runner integrations
```

### 3.2 Service Contract Enforcement

Every service directory MUST contain:

```text
services/<name>/
├── README.md                      # Purpose, ports, env vars, quickstart
├── Dockerfile
├── openapi.yaml OR grpc.proto     # Public contract
├── health/                        # /healthz, /readyz endpoints in code
├── config/                        # Constitution overlays; sane defaults
├── tests/
│   ├── unit/
│   ├── integration/
│   └── contract/                  # Contract tests against openapi/proto
└── CHANGELOG.md
```

### 5.2 Agent Definition Enforcement

CI validates that every `definition.yaml` in `agents/`:
1. Parses against `packages/python/coco-protocol/agent_contract.schema.json`
2. Every `tool_bindings.yaml` tool exists in the tool registry
3. Every `critic_agent_id` exists in the agent registry
4. Every `knowledge_sources.yaml` source exists in the corpus registry
5. Beat-Human benchmark has ≥ 3 tasks (Rung 4 gate)
6. Registered in top-level `registry.yaml`

### 5.5 Protocol Regeneration Rule

```text
Never hand-edit anything in generated/.
Never hand-edit generated stubs inside packages/*/coco-protocol/.

Workflow:
  1. Edit .proto file in protocols/v1/
  2. Run:  just proto-gen
  3. Commit the .proto + regenerated stubs together
  4. CI verifies stubs match .proto (no drift)
```

## 8. BUILD SYSTEM

### 8.1 The Two-Tier Build Approach

COCO deliberately does NOT use a single monolithic build tool (Bazel/Pants/Buck). Instead:

```text
TIER 1 — LANGUAGE-NATIVE BUILDS
  Python:      uv (fast, standard)
  TypeScript:  pnpm + Turborepo (task caching)
  Go:          go build
  Rust:        cargo

TIER 2 — CROSS-LANGUAGE ORCHESTRATION
  just         (task runner, thin wrapper)
  buf          (protobuf codegen)
  docker-compose (local topology)

RATIONALE:
  - Language-native tools are best-in-class for their language
  - Developers already know them
  - No custom BUILD file dialect to learn
  - Turborepo provides task caching across JS packages
  - just orchestrates cross-language workflows
```

## 10. THE `justfile` — TASK RUNNER

```text
# justfile — every developer's entry point
# Run:   just <task>
# List:  just --list

set dotenv-load

# ─── SETUP ─────────────────────────────────────────────────────
setup:                            # Fresh clone → ready to develop
    ./tools/setup/bootstrap.sh

install:
    uv sync --all-packages
    pnpm install --recursive --frozen-lockfile
    go work sync
    cargo fetch --workspace

doctor:                           # Diagnose local env issues
    ./tools/doctor.sh

# ─── PROTOCOL ─────────────────────────────────────────────────
proto-lint:
    cd protocols && buf lint
    cd protocols && buf breaking --against '.git#branch=main'

proto-gen: proto-lint
    cd protocols && buf generate
    ./tools/proto-sync.sh         # Copy stubs to per-language packages

# ─── LOCAL TOPOLOGY ───────────────────────────────────────────
up:                               # Start full local COCO topology
    docker compose -f infrastructure/docker/docker-compose.yaml up -d
    just db-migrate
    just db-seed
    @echo "COCO is up. Web: http://localhost:3000 · API: http://localhost:8080"

up-gpu:                           # Add local model serving
    docker compose \
      -f infrastructure/docker/docker-compose.yaml \
      -f infrastructure/docker/docker-compose.gpu.yaml \
      up -d

down:
    docker compose -f infrastructure/docker/docker-compose.yaml down

logs service:
    docker compose -f infrastructure/docker/docker-compose.yaml logs -f {{service}}

# ─── DATABASE ─────────────────────────────────────────────────
db-migrate:
    uv run --package coco-storage coco-migrate up

db-seed:
    uv run --package coco-storage coco-migrate seed

    docker compose -f infrastructure/docker/docker-compose.yaml \
      exec postgres psql -U coco_migrator -c "DROP DATABASE IF EXISTS coco;"

    just db-seed

# ─── FORMAT · LINT · TYPE ─────────────────────────────────────
fmt:
    uv run ruff format .

build-image service:
```

## 16. THE CONSTITUTION LOADER (Runtime Contract)

The `constitution/` directory is not documentation. It is loaded and enforced at runtime.

```python
# constitution/loader/validate.py
"""
Validates every YAML in constitution/ against its schema.
Run in CI on every PR touching constitution/.
Run at every service boot before accepting traffic.
"""

from pathlib import Path
import yaml
import jsonschema

CONSTITUTION_SCHEMAS = {
    "identity.yaml":               "identity.schema.json",
    "laws.yaml":                   "laws.schema.json",
    "voice.yaml":                  "voice.schema.json",
    "persona.yaml":                "persona.schema.json",
    "cognitive/state_machine.yaml": "state_machine.schema.json",
    "cognitive/depth_policy.yaml":  "depth_policy.schema.json",
    "cognitive/assumption_policy.yaml": "assumption_policy.schema.json",
    "cognitive/contradiction.yaml": "contradiction.schema.json",
    "cognitive/evidence.yaml":     "evidence.schema.json",
    "cognitive/modes.yaml":        "modes.schema.json",
    # ... policies/, methods/, evolution/
}

def validate_all(constitution_root: Path, schemas_root: Path) -> None:
    errors: list[str] = []
    for rel_path, schema_name in CONSTITUTION_SCHEMAS.items():
        yaml_path = constitution_root / rel_path
        schema_path = schemas_root / "constitution" / schema_name
        if not yaml_path.exists():
            errors.append(f"Missing: {rel_path}")
            continue
        try:
            doc = yaml.safe_load(yaml_path.read_text())
            schema = yaml.safe_load(schema_path.read_text())
            jsonschema.validate(doc, schema)
        except Exception as e:
            errors.append(f"{rel_path}: {e}")
    if errors:
        raise ConstitutionValidationError("\n".join(errors))
```

**Every service loads the constitution at boot:**
```python
# services/kernel/src/coco_kernel/boot.py

    constitution = load_constitution(strict=True)
    # constitution now available to depth_selector, response_composer, etc.
```
