0. THE EXPERT-BEATING PHILOSOPHY
A raw LLM answering a legal question is a precocious student. A COCO Legal Advisor answering the same question is a senior partner with instant access to every case, every statute, every treatise, an adversarial second attorney reviewing every word, and a permanent memory of every prior matter.

The gap is not the model. The gap is the system built around the model.

The Six Truths of Expert-Beating
text

TRUTH 1  — HUMANS FORGET; COCO REMEMBERS
           A human lawyer cannot hold every case in working memory.
           COCO retrieves the exact relevant precedent every time.

TRUTH 2  — HUMANS TIRE; COCO IS RELENTLESS
           A radiologist misses subtle findings after 8 hours.
           COCO's attention does not degrade across 10,000 images.

TRUTH 3  — HUMANS WORK ALONE; COCO WORKS IN PAIRS
           Every specialist is paired with an adversarial critic that
           attacks the work before the human user sees it.

TRUTH 4  — HUMANS ESTIMATE; COCO COMPUTES
           A human financial analyst estimates NPV in their head.
           COCO runs 10,000 Monte Carlo iterations in seconds.

TRUTH 5  — HUMANS CITE MEMORY; COCO CITES SOURCES
           Every claim is traceable to a primary source with a hash.
           Fabricated citations are structurally impossible.

TRUTH 6  — HUMANS SPECIALIZE NARROWLY; COCO COMBINES BROADLY
           A patent attorney rarely also runs monte-carlo financial
           analysis on the licensing model. COCO combines specialists
           in one mission without context loss.

1.2 Corpus Governance Rules
text

RULE 1  — EVERY DOCUMENT HAS PROVENANCE
          source URL, retrieval timestamp, SHA-256, license class
          
RULE 2  — LICENSE-COMPATIBLE OR EXCLUDED
          Copyrighted sources are used only under license
          (subscription APIs, licensed datasets, first-sale copies).
          Ambiguous sources default to EXCLUDE.

RULE 3  — VERSIONED, NEVER MUTATED
          Superseded documents remain queryable with status=superseded.
          New versions link to prior versions.

RULE 4  — AUTHORITATIVE > SECONDARY > TERTIARY
          Every source carries a credibility_class.
          Retrieval prefers primary sources when confidence conflicts.

RULE 5  — DOMAIN DIRECTOR OWNS THE REGISTRY
          Tier 2 Directors approve additions/removals to their corpus.
          Registry changes are code-reviewed and audited.

RULE 6  — QUARANTINE ON REFRESH FAILURE
          If a source becomes unreachable or license status changes,
          it enters quarantine — queryable with warning, but flagged.

RULE 7  — TENANT CORPORA ARE ISOLATED
          Enterprise tenants may add proprietary sources.
          Those sources are RLS-isolated and never leak to other tenants.
1.3 The Paired Critic Pattern
Law: Every Tier-3 Specialist has a paired Critic Agent. The Critic is defined in the same registry, spawned automatically alongside its specialist, and given the same knowledge access but a different cognitive stance.

text

                        SPECIALIST                CRITIC
                        ──────────                ──────
                        
    Stance:             Constructive              Adversarial
    Goal:               Produce best answer       Break the best answer
    Model:              Same tier                 Same or higher tier
    Knowledge:          Full domain corpus        Full domain corpus
    Tools:              Full suite                Read-only + verification tools
    Prompt bias:        "Best solution"           "Find the flaw"
    Method:             Domain methodology         Systematic attack patterns
    Output:             Deliverable + rationale   CriticReport (per Deep Spec 2 §7.2)
The Critic operates at Verification Level L9 (Constitutional §Dimension 9). If the Critic scores < rubric threshold, a RepairOrder is issued to the Specialist. Loop continues until pass or max_attempts.

5. The Cognitive Method (IRAC Enforced)
text

STEP 1 — INTAKE & JURISDICTION
   Parse document / query
   Detect governing law + venue
   Load jurisdictional context

STEP 2 — ISSUE SPOTTING (I)
   Extract every legally-material clause
   Classify each clause
   List candidate legal issues per clause

STEP 3 — PLAYBOOK COMPARISON (parallel)
   Compare each clause against tenant playbook (if present)
   Compare against firm-standard playbook (baseline)
   Rank deltas by severity: BLOCKER | MATERIAL | ADVISORY | STYLE

STEP 4 — RULE LOOKUP (R)
   For each issue:
     - Fetch controlling statutes (with effective_date verified)
     - Fetch binding precedents (with treatment_status verified)
     - Fetch persuasive authorities if binding is thin
   NEVER cite a case without KeyCite/Shepard's verification.

STEP 5 — APPLICATION (A)
   For each issue: apply rules to facts
   Identify counter-arguments
   Assess strength: STRONG | MODERATE | WEAK
   Compute probability ranges where appropriate

STEP 6 — CONCLUSION (C)
   Draft recommendation per issue
   Draft alternative language where redlining is needed
   Draft explanatory rationale (client-facing + attorney-facing versions)

STEP 7 — DELIVER TO CRITIC
   Package full analysis for C36_critic
   Wait for verdict
   Address every critic finding
   Iterate until critic recommendation = ACCEPT or ACCEPT_WITH_NOTES

STEP 8 — DELIVERABLE PACKAGING
   Attorney-facing memo (IRAC format)
   Client-facing summary (plain language)
   Redlined document (DOCX + PDF)
   Citation appendix with hyperlinks
   Assumption log
   Limitations disclosure
6. The Paired Critic (C36_critic)
YAML

id: C36_critic_adversarial_attorney
tier: tier_3_specialist
role: Adversarial senior counsel reviewing junior's work
model: same tier as specialist (frontier-reasoning-high)
prompt_bias: "Find every reason this analysis could be wrong."

attack_patterns:
  citation_verification:
    - Re-fetch every cited case
    - Verify quote appears verbatim in cited paragraph
    - Verify case is still good law (Shepard's/KeyCite)
    - Flag any citation format errors
    
  jurisdictional_attack:
    - Verify governing law matches jurisdiction of cited authorities
    - Flag if persuasive authority is being treated as binding
    - Verify effective_date of statutes cited is applicable
    
  counter_argument_check:
    - Search for cases holding the opposite conclusion
    - Verify those adverse cases are addressed or distinguished
    - Flag omissions
    
  playbook_completeness:
    - Verify every playbook clause was checked
    - Flag any material clauses missed
    
  reasoning_soundness:
    - Test each IRAC application step for logical validity
    - Flag conclusory statements without support
    - Flag assertions of "unsettled" law without evidence

output: CriticReport with per-attack-pattern findings
rejection_threshold: any BLOCKER finding rejects; > 2 MATERIAL findings rejects

   Parse mission objective

   For each domain operation:
     Write pytest unit tests defining expected behavior
     Write integration test fixtures

   Implement smallest code making tests pass (GREEN)

   Async I/O for all network/disk operations
   Custom exception hierarchies

STEP 5 — VERIFICATION LOOP
   Run ruff → fix
   Run mypy --strict → fix
   Run pytest with coverage → coverage must be ≥ 90%
   Run bandit → resolve security findings
   Run pip-audit → resolve CVEs
   Run complexity_analyzer → refactor functions > 10 CC

STEP 6 — INTEGRATION VALIDATION
   Docker build
   Container starts
   Health endpoint responds
   Integration tests pass against running container

STEP 7 — PERFORMANCE VALIDATION
   Baseline latency benchmarks
   Load test at expected concurrency
   Flag any endpoint > SLA target

   Package: code, tests, coverage report, docker image ref, benchmark results

6. HANDLING SPECIALIST FAILURE
Specialists fail. The system is designed to make failure safe.

6.1 Failure Modes
text

MODE 1 — CRITIC REJECTS OUTPUT
  → RepairOrder issued (max 3 attempts)
  → If exhausted: escalate to Tier 2 Director
  → Tier 2 Director may: assign different specialist, revise scope,
    request human input, or mark mission BLOCKED

MODE 2 — BENCHMARK REGRESSION DETECTED
  → Domain Director alerted (nightly)
  → Rollback to prior specialist version
  → Root cause analysis + fix
  → Re-shadow before promotion

MODE 3 — CORPUS STALENESS
  → Specialist emits warning in confidence caveats
  → Refresh job triggered
  → If corpus > 2x expected staleness: specialist marked DEGRADED

MODE 4 — TOOL UNAVAILABILITY
  → Fallback to secondary tool (per Tool Registry fallback chain)
  → If no fallback: specialist reports BLOCKED_INFO_NEEDED

MODE 5 — HUMAN EXPERT OVERRIDES DELIVERABLE
  → Human correction captured as training signal
  → Pattern analysis surfaces recurring issues
  → Domain Director evaluates method refinement
