DEEP SPEC 2 — THE FABRIC PROTOCOLS
System: DSRT COCO
Layer: Inter-Fabric Communication Standard
Status: Approved & Locked Specification
Governing Standards: Constitutional Dimensions 3 (Object Model), 4 (13 Fabrics), 7 (Mission Model), 9 (Verification Model); Article XIII (Cognitive Runtime)

0. PROTOCOL PHILOSOPHY
Fabrics do not know each other's internals. They exchange immutable, versioned, cryptographically-referenced messages through six protocols. Any fabric can be swapped, re-implemented, or scaled independently without touching another.

The Seven Governing Laws of the Protocols
text

LAW 1  — TYPED OR REJECTED
         Every message conforms to a schema. Untyped payloads are dropped at the boundary.

LAW 2  — VERSIONED OR REJECTED
         Every message carries a protocol version. Version drift triggers negotiation, never guessing.

LAW 3  — IMMUTABLE ONCE EMITTED
         Messages are append-only facts. Corrections come as new messages, never mutations.

LAW 4  — REFERENTIALLY TRACEABLE
         Every message carries mission_id, run_id, and causation_id. Full replay must be possible.

LAW 5  — PROVENANCE ATTACHED
         Every message carries emitter identity, timestamp, and correlation chain.

LAW 6  — IDEMPOTENT BY IDENTITY
         Every message has a unique idempotency_key. Duplicate delivery is a no-op.

LAW 7  — SIZE-BOUNDED
         Payloads above threshold are stored as artifacts; messages carry references, not blobs.
Transport Matrix
text

FABRIC-TO-FABRIC          TRANSPORT          SERIALIZATION       AUTH
─────────────────────    ──────────────    ─────────────────    ──────────────
Gateway ↔ Kernel          gRPC (bidi)       Protobuf             mTLS + JWT
Kernel ↔ Any Fabric       gRPC (bidi)       Protobuf             mTLS (internal)
Fabric ↔ Event Bus        NATS JetStream    JSON + CloudEvents   mTLS + NKey
Fabric ↔ Model            gRPC + SSE        Protobuf/SSE         mTLS + Provider Key
Agent ↔ Tool              gRPC (unary)      Protobuf             mTLS + Capability Token
External API              HTTPS + JSON      JSON Schema          OAuth 2.1 + mTLS
Protobuf is the source of truth. JSON representations shown below are canonical serializations for the wire, event bus, and human debugging.

1. THE ENVELOPE PROTOCOL (UNIVERSAL WRAPPER)
Every message across every protocol is wrapped in a CocoEnvelope. Bare payloads are never emitted.

protobuf

syntax = "proto3";
package coco.protocol.v1;

message CocoEnvelope {
  // ─── IDENTITY ────────────────────────────────────────────
  string envelope_id       = 1;   // ULID; globally unique
  string schema_uri        = 2;   // e.g. "coco://protocol/mission/v1/MissionRequest"
  string schema_version    = 3;   // Semantic version of payload schema

  // ─── ORIGIN ──────────────────────────────────────────────
  string emitter_fabric    = 4;   // e.g. "kernel", "intelligence", "execution"
  string emitter_component = 5;   // e.g. "A1_coco_director"
  string emitter_instance  = 6;   // Runtime instance identifier

  // ─── TENANCY ─────────────────────────────────────────────
  string organization_id   = 7;
  string user_id           = 8;

  // ─── CORRELATION (full causal chain) ─────────────────────
  string mission_id        = 9;
  string run_id            = 10;  // CognitiveRun ID (Article XIII)
  string task_id           = 11;  // Optional; empty for mission-level msgs
  string causation_id      = 12;  // envelope_id of message that caused this one
  string correlation_id    = 13;  // Groups related messages across time

  // ─── TIMING ──────────────────────────────────────────────
  int64  emitted_at_unix_ns = 14;
  int64  deadline_unix_ns   = 15; // Optional; 0 = no deadline

  // ─── DELIVERY GUARANTEES ─────────────────────────────────
  string idempotency_key   = 16;  // SHA-256 hex; identical => no-op
  int32  attempt_number    = 17;  // 1 on first send; incremented on retry

  // ─── PAYLOAD ─────────────────────────────────────────────
  bytes  payload           = 18;  // Serialized inner message (matches schema_uri)
  string payload_hash      = 19;  // SHA-256 hex of payload bytes

  // ─── CLASSIFICATION ──────────────────────────────────────
  Sensitivity sensitivity  = 20;  // For routing & audit
  repeated string tags     = 21;  // Free-form labels

  // ─── INTEGRITY ───────────────────────────────────────────
  string signature         = 22;  // Ed25519 sig over envelope hash (internal mTLS)
}

enum Sensitivity {
  SENSITIVITY_UNSPECIFIED = 0;
  PUBLIC                  = 1;
  INTERNAL                = 2;
  CONFIDENTIAL            = 3;
  RESTRICTED              = 4;   // PII, PHI, PCI, secrets
}
Envelope Validation Rules (enforced at every fabric boundary)
text

1. envelope_id must be a valid ULID.
2. schema_uri must resolve in the Schema Registry.
3. schema_version must be compatible with receiver's supported range.
4. emitted_at_unix_ns must not be in the future (>5s skew rejected).
5. deadline_unix_ns, if set, must be in the future.
6. payload_hash must match SHA-256(payload); otherwise integrity violation.
7. signature must verify against emitter's registered public key.
8. idempotency_key already seen within retention window → return prior result.
9. sensitivity=RESTRICTED requires tenant-scoped encryption at rest.
10. tenant fields (organization_id, user_id) must survive to every downstream msg.

6.4 Consumer Contract
text

1. Every consumer is durably registered with a consumer_name.
2. Consumers acknowledge messages within ack_wait (default 30s).
3. Failed processing → NAK with retry policy (exponential backoff, max 5 tries).
4. After max retries → published to `coco.{org}.{env}.dlq.{original_subject}`.
5. Consumers must be idempotent on envelope_id.
6. Ordering guarantees: strict order within (mission_id, subject_kind, subject_id).

9. VERSIONING & COMPATIBILITY POLICY
text

SEMANTIC VERSIONING FOR SCHEMAS
  MAJOR — Breaking change; consumers must upgrade
  MINOR — Additive; backward compatible (new optional fields, new enum values)
  PATCH — Documentation/clarification only

FIELD RULES
  1. Never renumber protobuf field tags.
  2. Never change field types.
  3. Never repurpose a removed field's tag (reserve it permanently).
  4. New fields must be optional with sensible defaults.
  5. New enum values must be tolerated by older consumers (unknown → UNSPECIFIED).

REGISTRY
  All schemas registered at:  coco://schemas/{protocol}/{version}/{message}
  All fabrics fetch schemas at boot and cache them.
  Schema Registry is a first-class fabric-adjacent service.

NEGOTIATION
  Envelope includes schema_version.
  Receivers advertise supported ranges per protocol.
  Mismatch → negotiation handshake, or graceful degradation to lowest common version.
  Unresolvable mismatch → NACK with SCHEMA_INCOMPATIBLE error, message DLQ'd.
